# Animated companion pets — first playable prototype

Scope: Feel Lab only. Original Kimi desktop/mobile repositories are untouched.

## Delivered

- Original, procedural, vertex-coloured cat (Mochi) and dog (Biscuit), based on the approved visual direction. These are an initial game-model interpretation, not an image-to-mesh conversion.
- Eleven articulated bones, distance/speed-driven walking, gentle ears/tail, blinks, idle sitting and a greeting in the studio. Decorative bounce is reduced for reduced-motion users.
- A `/pets/` 3D studio using the exact same models as gameplay, with rotate/zoom, walk/sit/hello and direct links to equip either pet.
- Bag picker, browser-local persistence, one active pet per player. No pet on unchanged links until selected. The explicit `pet=cat` or `pet=dog` demo links equip that companion.
- Bounded breadcrumb following with terrain/water/obstacle checks and a safe recall after teleports or an obstructed route. No player-body writes or pet rigid bodies.
- Existing avatar metadata carries the pet ID. No additional connection, server restart, position broadcast or emote-field reuse. Other clients show nearby companions. Mini games hide and reset the cosmetic follower; the park restores it afterwards.

## Cost controls

- Cat: 10,412 triangles / 8,961 vertices / 600,132 geometry bytes, shared across instances.
- Dog: 10,628 triangles / 6,834 vertices / 473,808 geometry bytes, shared across instances.
- One skinned draw plus one blob-shadow draw per displayed pet. One shared material and one shared 64×64 generated shadow texture; no new lighting or downloaded pet texture packs.
- Only the selected species is built until another species is needed. At most six remote pets on coarse-pointer devices, ten on desktop, within 30 metres; one local pet in addition.
- Local navigation at most 24 Hz, remote navigation at most 8 Hz, at most 20 ground probes per render step. Rigs use the existing game loop; no new gameplay RAF or timer.
- Gameplay module source approximately 27 KB, roughly 10 KB when gzipped as one measurement (actual separate HTTP transfer differs). Shared geometries remain cached on selection changes; per-instance skeletons are disposed.

Actual Chrome render and input checks, using two isolated clients (1280×900 desktop, 390×844 mobile emulation):

- Studio render, sit/hello, responsive layout and thumbnails rendered from the actual mesh.
- Keyboard movement and pet following; pet remains close enough to the player.
- Trusted touch start/move/end on the mobile joystick moves the player and the follower.
- Bag selection by click/touch; selection restored after reload.
- Each player sees the other's equipped species; changes/removal reach the peer.
- 100 selection requests do not stop the render loop or leak geometry.
- Chat still reaches the other client; mobile viewport scale remains 1.
- Deliberate lobby-socket close/reconnect restores pet metadata.
- Home entry/exit moves the pet with its owner; the exterior client stays connected.
- No page errors or pet-layer failure flags in the passing run.

Existing skateboard-audio browser regression also passes on desktop: four jump/flip/land cycles, live audio output, mute = zero, render continues.

## Limits

This is not a 100-real-player load certification or a physical iPhone/Android result. The 100-entry test validates the cosmetic rendering cap, not 100 fully rendered avatars. Pet care, trading, carrying, feeding and competitive mini-game pet mechanics are not implemented in this prototype. A recalled pet may briefly disappear/reappear on an unreachable route rather than pass through a wall. The existing foundation issues documented elsewhere are not represented as fixed by this feature.
